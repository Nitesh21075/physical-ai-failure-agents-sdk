Physical AI Failure Agents SDK

Startup and demo instructions for the persistent MineFailureResearcher agent.

Prerequisites: Linux with Python 3.11+, Docker and NVIDIA Container Toolkit for Isaac Sim, an OpenAI API key, and (for the browser comparison step) a Reactor API key.

1. Install

cd /home/ubuntu/physical-ai-failure-agents-sdk
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'

2. Configure the environment

Create .env in the repository root. It is git-ignored and must never be committed.

OPENAI_API_KEY=<your OpenAI key>
AGENT_MODEL=gpt-5.6-luna
REACTOR_API_KEY=<your Reactor key>

The launcher loads this file automatically. You may export the variables in your shell instead.

3. Start a research step

This invokes the official OpenAI Agents SDK Runner. The model chooses which of the seven bounded tools to call; the host does not pre-script the sequence.

.venv/bin/python scripts/run_agents_researcher.py \
  'Investigate roof-support failure in the mine. Inspect the world and prior evidence, then use at most one new Isaac experiment.' \
  --experiment-budget 2

Save the printed campaign_id. The first step may run a real Isaac experiment and return waiting_for_reactor with a pair_id.

Each new mine run records three real RTX views: a rover-oriented ego view, a smoothed invisible chase camera, and a fixed roof-support witness camera. Reactor is seeded only from the chase view after the content and object-visibility gate passes.

4. Start the dashboard

.venv/bin/python scripts/run_dashboard.py \
  --database runs/experiments.sqlite3 --port 8000

Open:

  • Agent control
  • Reactor browser capture
  • Evidence library

5. Complete the Reactor comparison

Use the pending pair link returned by the agent (normally /reactor?pair_id=<pair_id>). Start the real LingBot World 2/WebRTC session, record the future, and finish/save the capture. Do not replace it with a mock image or video.

6. Resume the same campaign

After the Reactor recording is saved, continue with the same campaign ID. The SDK session is persisted in runs/agent_sessions.sqlite3, so the agent can recover its prior conversation and evidence context.

.venv/bin/python scripts/run_agents_researcher.py \
  'Continue the research campaign now that the Reactor recording is complete.' \
  --campaign-id '<campaign-id>'

7. Verify locally

.venv/bin/ruff check src scripts tests
.venv/bin/pytest -q

Real Isaac validation uses the pinned nvcr.io/nvidia/isaac-sim:6.0.1 image and the repository's mine scripts. See the runtime guide for the exact call graph, tool boundary, persistence model, and E2E status.

The tracking camera follows Nova Carter by updating a non-physical camera transform from the measured rover pose. It never teleports the rover or triggers a failure. Raw frames and camera-pose provenance are stored below each run's camera/ directory.

Safety boundary

The model receives no shell, arbitrary Python, generic file-write, unrestricted Docker, or unrestricted Omniverse tool. Isaac runs are bounded and fixed to the mine experiment service; scientific evidence is stored under runs/.
